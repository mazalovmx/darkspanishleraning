# План: массовые улучшения UX/UI по руководству «HoMM-подобный интерфейс»

## Контекст

Игрок (единственный, ПК, мышь + клавиатура, испанский B1) за последние сессии несколько раз
упёрся в интерфейс: не понял, что делают кнопки, не нашёл первый шаг расследования, не смог
сохраниться, видел кнопку рыцарей до их появления. Точечные правки сделаны (подсказки на
кнопках, сводка задач, шаги в тетради улик, системное окно сохранения). Присланное руководство
даёт системную рамку, чтобы перестать чинить по одному экрану.

Цель плана: игрок за один взгляд понимает «где я, кто активен, что изменилось, что можно
сделать, сколько стоит, что будет после подтверждения» — на карте, в окнах и в бою.

## Что берём из руководства, а что нет

Игра личная, только Windows-ПК (docs/COPILOT.md, правило 14: не обобщать под консоли, мобильные,
веб). Поэтому:

- **Берём:** единые токены размеров/шрифтов/цветов; текст не мельче 18 px при 1080p; контраст;
  состояния кнопок и видимый фокус; «Esc = один шаг назад»; причины блокировки рядом с
  действием; не кодировать состояние только цветом; предпросмотр результата перед
  подтверждением (бой, покупка, стройка, экипировка); сравнение предметов; трекер цели на
  карте; предупреждение перед концом дня; масштаб интерфейса; полное управление с клавиатуры.
- **Не берём:** тач, геймпад, TV-safe-зоны, экранный диктор, вибрация, 4:3/21:9-перекомпоновка,
  портретный режим. Записать это в BACKLOG как сознательное исключение.

## Текущее состояние (что уже есть и что переиспользуем)

- Окно 1280×720, `stretch/mode=canvas_items`, `aspect=expand` (`game/project.godot`).
- Темы: `game/src/common/wood_theme.gd` (`build(font_size)`, `frame`, `icon`) для боковой панели,
  `game/src/common/parchment_theme.gd` (`apply(panel)`) для модальных окон.
- Размеры шрифтов заданы вручную в ~45 местах: 12–17 px (31 место), 20–34 px (13 мест) —
  большинство мельче рекомендованных 18 px.
- Каждое модальное окно собирает панель само (позиция, размер, поля): `campaign_panel.gd`,
  `evidence_notebook.gd`, `equipment_panel.gd`, `curriculum_panel.gd`, `ghost_panel.gd`,
  `side_panel.gd`, `economy/strategy_panel.gd`, `economy/market_panel.gd`, окно локации в
  `world_map.gd`, бой `combat/stack_arena.gd`.
- Список «какое окно открыто» повторён вручную в 6+ местах `world_map.gd` (`_end_turn`,
  `_update_preview`, `_unhandled_input`, обработчики кнопок, `_can_restart`).
- Настройки: `game/src/common/settings.gd` → `user://settings.json` (звук), экран настроек на
  титуле.
- Подсказки: `world_map._explain_buttons()` (испанский + английский), сводка задач
  `campaign_panel.summary()`, подсказка-гид `evidence_notebook.guide`.
- Проверка: `tools/run-tests.ps1` (71 набор), `game/tests/screenshots.gd` рендерит все экраны.

## Этапы

Каждый этап — отдельная задача: правки, тесты, запись в `docs/STATE.md`, один коммит, push.
Порядок по руководству: структура → состояния → ввод → раскладка → только потом украшения.

### Этап 0. Базовые снимки и аудит (без изменения поведения)
- Расширить `game/tests/screenshots.gd`: все окна в трёх состояниях (пусто / в работе / заполнено),
  плюс прогон при 1366×768 и 1920×1080.
- Новый `docs/UI_AUDIT.md`: таблица «экран → главная задача игрока → что видно всегда → что
  спрятано → найденные проблемы» по матрице экранов из руководства. Это список работ для
  этапов 3–6.

### Этап 1. Токены и общий каркас окна (P0)
- Новый `game/src/common/ui_tokens.gd`: шаг 8 px; отступы панели 24; интервалы 8/16/24/32;
  шрифты `BODY 18`, `CAPTION 16` (только для второстепенного), `H2 24`, `H1 30`, `NUMERIC 22`;
  смысловые цвета (текст, приглушённый, успех, предупреждение, ошибка, выделение) с проверенным
  контрастом ≥ 4.5:1 на пергаменте и на дереве.
- Новый `game/src/common/modal_frame.gd`: одна функция, которая строит затемнение, пергаментную
  панель, заголовок, строку-подсказку «что делать», область содержимого и нижний ряд с кнопкой
  «Volver». Переиспользует `parchment_theme.apply`.
- Перевести окна на каркас и токены по одному (журнал задач → тетрадь → уроки → экипировка →
  поселение → рынок → местные дела → рыцари → окно локации). Убрать ручные `font_size`-числа.
- Тест `ui_tokens_test.gd`: контраст пар цветов; в каждом окне нет текста мельче `CAPTION`;
  кнопка закрытия в пределах экрана при 1280×720.

### Этап 2. Навигация и ввод (P0)
- В `world_map.gd` завести один список модальных окон и функции `_modal_open()` /
  `_top_modal()`; заменить им все ручные перечисления (сейчас новое окно надо дописывать в 6+
  мест — источник ошибок).
- `Esc` закрывает верхнее окно на один уровень (сейчас работает только у рыцарей); `Esc` на
  карте — снять выделение.
- Видимый фокус клавиатуры в обеих темах (рамка, отличная от «выбрано»); `Tab` ходит по
  элементам окна; при открытии фокус на главном поле ввода.
- Горячие клавиши с показом в подсказках: `E` конец дня, `J` задачи, `C` тетрадь, `L` испанский,
  `I` экипировка, `Ctrl+S` сохранить. Не срабатывают, пока фокус в поле ввода.
- Тест `ui_navigation_test.gd`: каждое окно открывается и закрывается с клавиатуры; `Esc`
  закрывает ровно одно; горячие клавиши не срабатывают при наборе текста.

### Этап 3. Карта: состояние и следующая цель (P0)
- Трекер цели в боковой панели: одна строка «Ahora: …» из `campaign_panel.summary()` (первая
  задача ▶), клик открывает журнал. Логику «следующий шаг» вынести из панели в
  `campaign_state.next_step(world)`, чтобы журнал и трекер читали одно и то же.
- Перегруппировать панель по смыслу с подзаголовками: Héroe · Turno · Investigación · Partida.
- Конец дня: предупреждение только когда есть значимое незавершённое (неиспользованное
  движение героя рядом с целью, доступная и неоплаченная постройка), с «no avisar más»
  (в `settings.gd`).
- Подсказка по клетке при наведении: тип местности и стоимость, локация, шахта, охрана.
- Не только цвет: маршрут «не хватает хода» — пунктир + текст, а не только красный.

### Этап 4. Причины и предпросмотр последствий (P0)
- Единый формат строки результата у всех действий: «Falta: … / Cuesta: … / Quedará: …».
- Поселение и рынок (`strategy_panel.gd`, `market_panel.gd`): до подтверждения показывать
  стоимость, остаток ресурсов после, недостающие условия по именам.
- Экипировка (`equipment_panel.gd`): сравнение выбранной вещи с надетой в том же слоте
  («Defensa +2 ↑, Movimiento −1 ↓»); причина, почему нельзя надеть; редкость словом, не только
  цветом. Действия без перетаскивания уже есть — сохранить.
- Заблокированные задачи и дела: всегда текст причины (частично есть в `campaign_state.reason`,
  `side_investigations.reason`) — вывести его в списках, а не только в теле.

### Этап 5. Бой (P0)
`game/src/combat/stack_arena.gd`, расчёты в `stack_battle.gd`:
- Три разных состояния цели (допустимая / под курсором / подтверждённая) разной формой, не
  оттенком.
- Предпросмотр до подтверждения: урон (диапазон), ожидаемые потери, ответный удар, путь и
  стоимость хода. Считать функцией в `stack_battle.gd`, окно только показывает.
- Лента очерёдности: текущий отряд крупнее, следующий очевиден.
- Сворачиваемый журнал боя из структурированных событий: источник → действие → цель → итог.
- Стабильный порядок кнопок действий, клавиши на кнопках.

### Этап 6. Масштаб интерфейса и разрешения (P1)
- Настройка «Tamaño de la interfaz» 100/125/150 % в `settings.gd` и экране настроек: через
  `get_window().content_scale_factor`; панели должны перестраиваться, а не обрезаться.
- Проверка 1366×768, 1920×1080, 2560×1440: карта остаётся главной областью, критичный текст не
  обрезан. Где не помещается — прокрутка внутри окна, не уменьшение шрифта.
- 200 % из руководства для окна 1280×720 недостижимы без полной перекомпоновки — ограничиться
  150 % и записать ограничение в BACKLOG.

### Этап 7. Длинные списки и мелкая обратная связь (P1/P2)
- Экипировка и словарь: фильтр по типу, сортировка, отметка «новое».
- Короткие ответы на действие: «−300 oro» у счётчика ресурса, отметка выполненной цели,
  подсветка слота при надевании. Настройка «Reducir animaciones».
- Смысловые имена звуков (`ui.confirm`, `ui.error`, `inventory.equip`…) вместо путей к файлам.

## Ограничения и риски

- Правило «меньше пяти файлов на задачу»: этап 1 дробится на подзадачи по одному-двум окнам.
- Шрифт 18 px вместо 13–16 в окне 1280×720 съест место: окна придётся укрупнять или вводить
  прокрутку; боковая панель карты — самое тесное место, для неё возможен `CAPTION 16`.
- Тесты привязаны к текстам и размерам (`get_global_rect`, `item_count`) — после каждого окна
  гонять его набор, после этапа — полный прогон.
- Игровую логику, сохранения и испанские проверки этапы не меняют; исключение — расчёт
  предпросмотра боя, он только читает состояние.
- Всё UI остаётся на испанском с короткой английской строкой в подсказках, как сейчас.
